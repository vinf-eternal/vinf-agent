## 一、设计目标

> 开源版定位（引自 V∞-AUD-044 §3.2）：**个人认知外延系统·轻量**。零代码门槛、纯文本配置、单机自治。让「不会写代码但想要专属 Agent」的普通用户，fork 一份配置即获得可复现的认知外延。

三条硬约束：

1. **C-01 模态上限**：全部配置为 md 文本 + 轻量规则引擎，不承诺认知涌现，只做认知外延；
2. **C-02 审计纪律**：同系统自检仅能做逻辑纠错，不做确权；文档对外表述禁用「AGI/意识/认知跃迁」；
3. **M33 双层势垒**：外部输入走 PublicBuffer（外层），用户私人记忆走 PrivateCore（内层），两层读写隔离。

## 三、双层循环设计（参考 pi-agent 循环结构）

> 参考实现：`pi-main/packages/agent/src/agent-loop.ts` 的 `runLoop`——外层 `while(true)` 处理 steering/follow-up，内层 `while(hasMoreToolCalls)` 处理工具调用。

### 3.1 两层语义

| 层 | 名称 | 职责 | pi 对应 |
|----|------|------|---------|
| 外环 | 交互循环 | 接收用户消息 → 生成回复 → 等待下一消息（含 steering 注入） | 外层 `while(true)` + `getSteeringMessages()` |
| 内环 | 工具循环 | 模型请求工具 → 执行 → 结果回填 → 再次生成，直到无工具调用 | 内层 `while(hasMoreToolCalls)` |

### 3.2 外环交互循环

```
while (会话未结束):
    1. 收集 pending messages（用户新输入 / steering 注入）
    2. 若有 pending → 注入上下文
    3. 调用 LLM 生成回复（携带完整上下文 + 系统提示词）
    4. 若 stopReason == error/aborted → 退出会话
    5. 进入内环（处理工具调用）
    6. 生成回复给用户，等待下一输入
```

### 3.3 内环工具循环

```
while (hasMoreToolCalls):
    1. 从回复中提取 toolCall 列表
    2. 若 stopReason == length → 全部视为截断，fail 所有工具（防残缺参数执行）
    3. 否则并行/顺序执行工具
    4. 工具结果回填上下文
    5. 再次调用 LLM（基于回填后的上下文）
    6. 若新回复无工具调用 → hasMoreToolCalls = false
```

### 3.4 开源版裁剪

- **不做**：多 Agent 协作、跨域实验、深层势垒调控、完整三轨审计；
- **做**：外环 + 内环基础循环、单 Agent 工具执行、记忆读写门（B_in 隔离）。

## 四、分层配置优先级（B_out 配置层）

```

project/agents.md  ← 项目变项
global/agents.md   ← 全局常项（最低）
```
